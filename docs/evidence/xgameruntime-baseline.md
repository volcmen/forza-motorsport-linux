# WineGDK XGameRuntime bridge baseline

Date: 2026-09-01

This evidence is revision-bound. It records the isolated WineGDK base used for
the XGameRuntime/Xodus bridge and distinguishes source compilation from Wine PE
runtime execution. It is not proof that Forza, Xbox authentication, invites, or
the installed compatibility tool work.

## Canonical source and isolation

The source worktree was created from
[`Weather-OS/WineGDK`](https://github.com/Weather-OS/WineGDK) at the exact base
`b03ba49c4f326c36aa6930fbe6cf72841ef3738c` on the local branch
`feature/xodus-social-invite-bridge`. Its only configured remote was:

No controller/storage build directory, installed Proton tree, game prefix, or

## Toolchain and configure contract

The baseline used Wine configure 11.14 generated by GNU Autoconf 2.73, GCC
16.2.1, Clang 22.1.8, GNU Make 4.4.1, Bison 3.8.2, and Flex 2.6.4. From the fresh
build directory, the exact configure command was:

```bash
../winegdk-xgameruntime/configure --enable-win64 --without-ffmpeg --without-opencl
```

The first focused build failed before linking because `dlltool` was absent from
the normal process `PATH`. No package was installed. Later compile/link commands
used the existing user-local Wine build-tool wrapper at:

```text
$HOME/.local/share/forza-motorsport-linux/build-tools/bin/dlltool
```

and prepended that directory to `PATH`. The focused build command was:

```bash
PATH="$HOME/.local/share/forza-motorsport-linux/build-tools/bin:/usr/local/sbin:/usr/local/bin:/usr/bin" \
  make -C dlls/xgameruntime -j2
```

## Clang 22 prerequisite result

The pinned base does not compile with this toolchain. The initial RED exposed
`__uuidof` failures for `TaskQueuePortImpl`, `TaskQueuePortContextImpl`,
`TaskQueueImpl`, and `IUser`; after those were corrected using the UUID values
already declared next to each class, linking exposed C/C++ linkage mismatches
for the exported runtime globals and Wine Unix-call dispatcher.

A narrow prerequisite patch adds the existing UUIDs as `DECLSPEC_UUID` class
annotations, gives the XGameRuntime globals C linkage, and makes
`include/wine/unixlib.h` C++-safe. With only those compile prerequisites, the
focused PE/Unix compile and link gate is **GREEN**. This patch does not add the
social bridge or alter the live installation. The resulting artifact hashes
are intentionally not a release contract because subsequent source work will
replace them.

The exact upstream build incompatibility and equivalent fix shape are also
documented in
[`Weather-OS/WineGDK` issue 62](https://github.com/Weather-OS/WineGDK/issues/62).

## Task 0.5 XUser and main-IPC checkpoint

The prerequisite lifetime implementation is local WineGDK commit
`27028929130a168a5ed355c3740b2c8e00bb9c62`
(`xgameruntime: own user handles and main IPC lifetime`). It keeps the main
Xodus async action and worker-owned descriptor alive through explicit bounded
stop/join, reserves the append-only Unix call IDs `0..10`, rejects stale XUser
handles by initialization epoch and main generation, and balances async outer,
worker, result, handler, and invoker ownership. At that checkpoint the social
operation IDs `5..10` remained deliberate `STATUS_NOT_IMPLEMENTED`
reservations. They are implemented by the later transport checkpoint below.

The first GE-Proton-hosted experiment exposed an important harness error:
GE-Proton's own `lib/wine` directory precedes `WINEDLLPATH`, so its installed
`xgameruntime.so` was being paired with the new PE DLL. The checked-in
`scripts/test-xgameruntime-bridge` gate avoids that false positive by making an
isolated same-filesystem hard-link overlay of the selected GE-Proton tree,
unlinking only the two overlay XGameRuntime entries, installing the exact build
outputs there, and verifying byte parity with `cmp` before execution. It never
changes the selected GE-Proton tree or the live Forza prefix.

The hermetic gate uses only a private mode-`0600` Unix socket and synthetic Ping
frames. Its 2026-09-01 results were:

| Mode | Result | Coverage |
| --- | --- | --- |
| Fixture disabled | **GREEN: 21 tests, 0 failures, 1 skipped** | PE load, canonical XThreading/XUser queries, manual-queue XAsync lifecycle, and null validation. |
| Socket absent | **GREEN: 29 tests, 0 failures** | Two bounded initialize failures followed by repeatable uninitialize. |
| Synthetic Ping fixture | **GREEN: 27 tests, 0 failures** | Two complete initialize/Ping/uninitialize lifecycles over the exact new PE and Unix pair. |

## Xodus social transport checkpoint

WineGDK commit `d387ceda67abd663e5243ce11e1ea4e7b63b7aff`
(`xgameruntime: add bounded Xodus social transport`) implements the reserved
Unix calls without changing the append-only IDs:

- `5..7` own the single XDSI invite-activation subscription, validate the
  little-endian frame length, cap the URI at 4096 bytes, and admit only the
  expected `ms-xbl-multiplayer://inviteAccept` shape;
- `8..10` own independent XDUI operations for the full and invite-only social
  overlay, including immediate terminal replies, blocking completion, and
  shutdown-driven cancellation;
- all descriptors are close-on-exec, writes suppress `SIGPIPE`, transfer
  deadlines cover the complete read or write rather than each partial byte,
  and stop requests wake blocked readers before teardown;
- the socket must be an absolute Unix socket owned by the current uid with
  exact mode `0600`. Xodus creates the production socket with that mode.

The exact-artifact gate now runs a native call-table contract suite before the
existing GE-Proton-hosted PE suite. The native fixture covers private socket
permissions, accepted and rejected invite URIs, slow-drip deadline enforcement,
XDUI terminal states, an immediate service-side refusal, and cancellation. The
full 2026-09-01 gate result remained green: seven native transport cases, then
21 PE baseline assertions with one intentional skip, 29 bounded-refusal
assertions, and 27 synthetic Ping lifecycle assertions, all with zero failures.
