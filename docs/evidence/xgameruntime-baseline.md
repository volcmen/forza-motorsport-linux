# WineGDK XGameRuntime bridge baseline

Date: 2026-09-01

This evidence is revision-bound. It records the isolated WineGDK base used for
the XGameRuntime/Xodus bridge and distinguishes source compilation from Wine PE
runtime execution. It is not proof that Forza, Xbox authentication, invites, or
the installed compatibility tool work.

## Canonical source and isolation

The source worktree was created from
[`Weather-OS/WineGDK`](https://github.com/Weather-OS/WineGDK) at the exact base
`b03ba49c4f326c36aa6930fbe6cf72841ef3738c` on the local branch
`feature/xodus-social-invite-bridge`. Its only configured remote was:

```text
origin  https://github.com/Weather-OS/WineGDK.git (fetch)
origin  https://github.com/Weather-OS/WineGDK.git (push)
```

The source and build trees are separate, user-owned directories below the
integration repository's ignored `.worktrees` directory:

```text
.worktrees/winegdk-xgameruntime
.worktrees/winegdk-xgameruntime-build
```

No controller/storage build directory, installed Proton tree, game prefix, or
live Xodus checkout was reused.

## Toolchain and configure contract

The baseline used Wine configure 11.14 generated by GNU Autoconf 2.73, GCC
16.2.1, Clang 22.1.8, GNU Make 4.4.1, Bison 3.8.2, and Flex 2.6.4. From the fresh
build directory, the exact configure command was:

```bash
../winegdk-xgameruntime/configure --enable-win64 --without-ffmpeg
```

The first focused build failed before linking because `dlltool` was absent from
the normal process `PATH`. No package was installed. Later compile/link commands
used the existing user-local Wine build-tool wrapper at:

```text
$HOME/.local/share/forza-motorsport-linux/build-tools/bin/dlltool
```

and prepended that directory to `PATH`. The focused build command was:

```bash
PATH="$HOME/.local/share/forza-motorsport-linux/build-tools/bin:/usr/local/sbin:/usr/local/bin:/usr/bin" \
  make -C dlls/xgameruntime -j2
```

## Base source and generated inputs

`dlls/xgameruntime/Makefile.in` defines the PE module
`xgameruntime.dll`, Unix library `xgameruntime.so`, and this source set:

- `main.c`, `xodusprovider.idl`, and `provider.idl`;
- `WineCoreUAP/Foundation/IWineAsync.cpp` and `IWineVector.cpp`;
- threading sources `XAsync.cpp`, `XTaskQueue.cpp`, `WaitTimer.cpp`, and
  `ThreadPool.cpp`;
- system sources `UserImpl.cpp`, `XThreading.cpp`, `XGameRuntimeFeature.cpp`,
  `XSystem.cpp`, `XSystemAnalytics.cpp`, `XNetworking.cpp`, and `XUser.cpp`;
- Xodus sources `Structs.cpp`, `IPCLayer.cpp`, `XodusService.cpp`,
  `XodusXMLBuilder.cpp`, and `Unix/socket.c`;
- `GDKComponent/InitInternalGDKC.cpp`.

The two IDL inputs generate the build-tree headers `xodusprovider.h` and
`provider.h`, which are consumed by the C++ sources and are not hand-edited.
The base Unix dispatch table contains exactly three append-only operation IDs:

```text
0 conn_socket
1 poll_socket
2 send_frame
```

The expected focused outputs are:

```text
dlls/xgameruntime/x86_64-windows/xgameruntime.dll
dlls/xgameruntime/xgameruntime.so
```

## Clang 22 prerequisite result

The pinned base does not compile with this toolchain. The initial RED exposed
`__uuidof` failures for `TaskQueuePortImpl`, `TaskQueuePortContextImpl`,
`TaskQueueImpl`, and `IUser`; after those were corrected using the UUID values
already declared next to each class, linking exposed C/C++ linkage mismatches
for the exported runtime globals and Wine Unix-call dispatcher.

A narrow prerequisite patch adds the existing UUIDs as `DECLSPEC_UUID` class
annotations, gives the XGameRuntime globals C linkage, and makes
`include/wine/unixlib.h` C++-safe. With only those compile prerequisites, the
focused PE/Unix compile and link gate is **GREEN**. This patch does not add the
social bridge or alter the live installation. The resulting artifact hashes
are intentionally not a release contract because subsequent source work will
replace them.

The exact upstream build incompatibility and equivalent fix shape are also
documented in
[`Weather-OS/WineGDK` issue 62](https://github.com/Weather-OS/WineGDK/issues/62).

## Baseline tests and limitations

The base `dlls/xgameruntime/tests/xgameruntime.c` calls only
`RoInitialize(RO_INIT_MULTITHREADED)` and `RoUninitialize()`. It never loads or
queries XGameRuntime, initializes Xodus, sends Ping, or exercises async
lifetime. A pass would therefore be vacuous for this bridge.

The focused Wine test target compiled its PE test executable but stopped before
test dispatch:

```text
Wrong -T argument, ./server/wineserver does not exist
```

The dedicated directory contains only the focused XGameRuntime build, not a
complete Wine tree. Therefore the baseline status is:

| Check | Status | Result |
| --- | --- | --- |
| Exact source/remotes/toolchain capture | **GREEN** | Revision and local isolation are recorded above. |
| Focused PE and Unix compile/link | **GREEN after prerequisite patch** | Both expected artifacts were produced without installing a package. |
| Existing test semantics | **VACUOUS** | The only assertion checks COM initialization. |
| Existing Wine PE test execution | **BLOCKED before dispatch** | The partial build has no `server/wineserver`; no test assertion ran. |
| XThreading query, async, Unixlib-failure, and Ping framing tests | **PENDING** | These focused prerequisite tests must be added before feature behavior. |
| Live installation or Forza/Xbox validation | **NOT RUN** | No live service, prefix, Steam option, keychain, or game process was touched. |
