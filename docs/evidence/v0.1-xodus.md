## Explicit Join action regression

The legacy service already revalidated a friend's actual activity when a Join
request was executed. Its snapshot builder nevertheless advertised Join only
when a free-form presence string contained the exact words `Forza Motorsport`.
That heuristic hid the existing action for otherwise valid friends.

The regression test `every_friend_exposes_a_revalidated_join_action` was first
changed to require Join for a friend without that presence phrase. It failed
with `left: Invite` and `right: Join`. The production change then made every
friend row expose Join while retaining action-time activity validation and its
safe unavailable error. The targeted test passed after the change.

## Safe-test review and result

The offline test list was inspected before execution:

```bash
rtk cargo test --workspace --offline -- --list
```

It listed 79 tests: 73 ordinary tests and 6 ignored tests. The only unignored
test that can contact a Microsoft/Xbox endpoint was
`api::live::test::test_get_xbox_live_dev_token`. Its source creates device
credentials and exchanges the token with the live service, so it was excluded.
The six ignored `auth` tests also contain live/account paths and remained
ignored: `test_minecraft_win_auth`, `test_forza_motorsport_sisu`,
`test_forza_xsts_with_title_token`, `test_forza_title_endpoints`,
`test_forza_xsts_full_chain`, and `test_forza_xsts_one_device`.

```bash
rtk cargo test --workspace --offline -- --skip test_get_xbox_live_dev_token
```

Result: **72 passed, 6 ignored, 1 filtered out** across 9 suites in 0.03 s.

The source review also identified synthetic tests that bind temporary local
Unix or loopback sockets. The task-owner ruling permits those fixture-only
tests; they neither start `xodus-service` nor use the production Xodus socket.
No account, login, Secret Service item, production/account socket,
Microsoft/Xbox endpoint, installed artifact, or game was used. Temporary local
fixture sockets and loopback HTTP were used only by the hermetic tests.
