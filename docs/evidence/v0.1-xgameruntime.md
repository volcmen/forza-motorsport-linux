## Tests-first and regression results

The original interface and relay tests were ported before implementation. The
first reconstruction build reached a pre-existing `__uuidof` failure in
`XTaskQueue.cpp`, which prevented a PE artifact on the parity checkpoint.

The fix round first ran the expanded PE suite against the original unregister
implementation. It reached `invite relay ready for synthetic fixture` and
timed out because an immediate task-queue callback self-unregistered while the
registration lock was held. After the implementation change, the same private
fixture passed:

```text
53 tests executed (0 marked as todo, 0 as flaky, 0 failures), 0 skipped.
```

The PE test uses a non-null manual completion queue, closes the caller's
original handle after registration, delays a callback while another thread
calls unregister with `wait=TRUE`, and proves unregister returns only after the
callback is released. It also covers immediate-queue callback self-unregister,
registration-slot reuse, and distinct nonzero tokens. `QueryApiImpl` is used to
query `IXGameUiImpl2`; the interface methods retain their IDL signatures and
are not added as standalone exports.

Callbacks now execute outside the shared registration lock. Queued work owns a
registration reference, only executing callbacks participate in the wait
count, removal suppresses queued callbacks that have not started, and the
duplicated queue handle is released with the last registration reference.

The social UI and relay logs no longer include session configuration,
template, session ID, invitation text, custom activation context, or the full
activation URI. A source-policy gate rejects those log arguments and checks the
queue and `IXGameUiImpl2` regression-test markers.

  linkage when included by C++ translation units;

  mixed C/C++ boundary.

These are compiler/ABI declarations only; no task-queue algorithm or unrelated
runtime behavior was copied from another branch.
