## Tests-first and regression results

The original interface and relay tests were ported before implementation. The
first reconstruction build reached a pre-existing `__uuidof` failure in
`XTaskQueue.cpp`, which prevented a PE artifact on the parity checkpoint.

The first fix round ran the expanded PE suite against the original unregister
implementation. It reached `invite relay ready for synthetic fixture` and
timed out because an immediate task-queue callback self-unregistered while the
registration lock was held. The second fix round then added a real manual-queue
regression before its lifecycle change. Unregistering before dispatch suppressed
the callback but retained one threading reference. After the lifecycle fix, the
final private fixture passed:

```text
61 tests executed (0 marked as todo, 0 as flaky, 0 failures), 0 skipped.
```

The PE test uses a non-null manual completion queue, closes the caller's
original handle after registration, delays a callback while another thread
calls unregister with `wait=TRUE`, and proves unregister returns only after the
callback is released. It also covers immediate-queue callback self-unregister,
registration-slot reuse, distinct nonzero tokens, and unregister-before-dispatch
after every caller-owned queue handle is closed. `QueryApiImpl` is used to query
`IXGameUiImpl2`; the interface methods retain their IDL signatures and are not
added as standalone exports. The returned UI interface is also called directly
to prove `QueryInterface(..., NULL)` returns `E_POINTER`.

Callbacks now execute outside the shared registration lock. A pending-list
reference and submitting-worker reference keep each post alive only while it
can still be claimed or submitted. The queue callback receives an opaque,
monotonic token rather than a dereferenceable post pointer. Unregister and the
callback trampoline atomically compete to claim that token under the same lock;
unregister can therefore suppress and release undispatched posts without
dispatching or terminating a borrowed queue. Only executing callbacks
participate in the external wait count, and the duplicated queue handle is
released with the last registration reference.

The social UI and relay logs no longer include a requesting-user handle,
session configuration, template, session ID, invitation text, custom activation
context, or the full activation URI. A source-policy gate rejects those log
arguments and checks the queue and `IXGameUiImpl2` regression-test markers.

runtime behavior was copied from another branch.
