## Tests-first result

The interface IDL and query/relay tests were ported before implementation. A
fresh out-of-tree configure using the host Clang 22 toolchain first stopped in
pre-existing component code: default C++ mode lacked `std::is_base_of_v`; a
C++17 retry reached `__uuidof` failures in `XTaskQueue.cpp`. The test target
itself compiled, but the focused PE module could not reach the newly added
classes on this unpatched legacy base. This is the observed RED rather than an
invented missing-symbol result.

The integration fixture scanner was also run tests-first. It failed because
`tools/xgameruntime-legacy-transport-test.py` did not exist, then passed after
the fixture was added.

## Disposable build contract

All build-system generation stayed in disposable source material made from a
clean `git archive`; the tracked component tree remained generation-free. The
disposable source material ran:

```bash
autoreconf -f
uv run ./dlls/winevulkan/make_vulkan
./tools/make_specfiles
./tools/make_requests
```

Configure used GCC 16.2.1 for Unix code and the already-installed Clang 20.1.8
bundle for the PE target, with the same `-std=gnu++17` form recorded by the
prior successful build configuration. The user-local `dlltool` wrapper was
prepended to `PATH`; no package was installed. The configure options were:

```text
--enable-win64 --without-ffmpeg --without-opencl
```

The Unix target and the focused PE tests target passed. The complete focused
PE module did not build: Clang 20 reported that `TaskQueuePortImpl`,
`TaskQueueImpl`, and `TaskQueuePortContextImpl` had no GUID at the legacy
`__uuidof` expressions in `XTaskQueue.cpp`. Clang 22 additionally failed in
the legacy C++ ABI headers. Correcting either requires prerequisite source
changes outside the eight-file reconstruction, which this task deliberately
did not make.

## Native transport gate

The direct native gate loaded the seven-entry `__wine_unix_call_funcs` table
with fixed indexes `3`, `4`, `5`, and `6`. It used only a mode-`0600` local
Unix socket and synthetic data. The gate passed all of these cases:

- `XDSI` subscription and a length-prefixed invite delivered one byte at a
  time;
- a length greater than 4096 was rejected;
- subscriber close was idempotent and a missing socket returned connection
  refusal;
- `XDUI` status zero mapped to success and nonzero mapped to failure;
- the synthetic invite value was never printed.

The native library was loaded with the disposable build tree's `dlls/ntdll`
directory on `LD_LIBRARY_PATH`. No Xodus process or account service was
started.
