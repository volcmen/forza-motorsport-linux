# Forza Motorsport Linux v0.1 Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconstruct and verify the source generation that currently launches Forza Motorsport, validate it through a recoverable live matrix, and publish a source-only v0.1 repository plus narrowly scoped upstream evidence.

**Architecture:** The integration repository remains the sole user-facing entry point. A clean legacy Xodus revision and a reconstructed Wine/XGameRuntime branch form the v0.1 runtime line; the newer WineGDK/Xodus work remains a separately labeled experiment. A machine-readable manifest controls claims, a recoverable installer protects the live setup, and external publication occurs only after an explicit review of exact targets and text.

**Tech Stack:** Git and linked worktrees, Python 3.11+ with `uv`, Bash, systemd user services, Rust/Cargo, Wine build tooling, TOML/JSON manifests, GitHub CLI, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-forza-v0.1-publication-design.md`

## Global Constraints

- AppID is exactly `2440510`; the tested compatibility-tool line is `GE-Proton11-3-FM`.
- Preserve the currently working installation until a digest-bound candidate plan has been reviewed.
- Never mutate the user-supplied `xgameruntime.dll.threading`; do not record or publish its hash.
- Publish no Microsoft binary, GameConfigHelper, game asset, token, proof key, XUID, account handle, invite URI, private path, or unredacted log.
- Keep KDE Wallet through Secret Service; do not install GNOME Keyring or enable plaintext credential storage.
- Keep Xodus disabled and session-scoped; never enable it as a login service.
- Treat automatic incoming Xbox invite notifications as unsupported.
- Keep the newer WineGDK `ef069c85c8b3ee049971a9e22a317309b30bb09f` and Xodus `b76690da6ff59ace8981bf0428cd729fcd15673d` pair out of v0.1.
- Use isolated worktrees for component source reconstruction; preserve every pre-existing dirty checkout.
- Run no live Xbox endpoint from CI or automated tests; fixtures use synthetic identities and URIs.
- Do not create a repository, fork, remote branch, issue comment, pull request, tag, or release until Task 8 presents the exact action set for approval.
- The blog is outside this plan.
