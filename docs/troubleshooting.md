# Troubleshooting

Start with the read-only check:

```bash
~/.local/bin/forza-doctor
```

`FAIL` means a prerequisite is absent or cannot be trusted. `WARN` for controller and mountmgr state means the exact reviewed original was found and can be considered for the documented patch fallback. `FAIL` for that state means do not patch: the hash, layout, or installed patcher is not recognized.

If Secret Service fails, ensure KDE Wallet exposes `org.freedesktop.secrets` in the user D-Bus session or has an activatable KDE Secret Service provider. Do not add GNOME Keyring solely for this integration.

If the launcher reports that the service cannot start, do not manually start the unit: the service intentionally requires the launcher's one-shot pending ownership token. Launch through the Steam option generated by `scripts/print-steam-options`. If the socket readiness wait fails, inspect the user journal locally and remove personal tokens, IDs, gamertags, invite data, and account details before sharing an excerpt.

If installation or a later startup reports a recovery problem, leave `~/.local/state/forza-motorsport-linux/transaction-journal` and its recovery directory in place. They are recovery evidence. The installer retains material rather than unlinking an unproven mutable name. Review retained files manually before any purge.

The runtime-component transaction uses a different state root: `~/.local/state/forza-motorsport-linux/runtime-transactions`. If the launcher reports `prepared`, `installing`, `rolling_back`, or `recovery_required`, keep the game closed and prove `xodus-forza.service` is inactive. Reuse the exact absolute arguments from the reviewed plan and run `install-runtime-components status`; then resume the recorded operation with `rollback` or `restore-runtime`. A Wine-only restoration in progress deliberately rejects full `rollback`, and vice versa. Do not delete the journal, backups, stages, or recovery files to bypass the launch gate. If the tool cannot prove one exact transaction or reports `recovery_required`, preserve everything for inspection.

If uninstall warns that a file was modified, that is deliberate: it preserves the file and removes only manifest-proven content. Restore patch backups separately with the recorded patch backup manifest; uninstall does not alter compatibility-tool files.
